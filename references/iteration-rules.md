# 修改班级管理工作台 HTML 的安全纪律

这份文件 40 万字符、单文件内联 CSS/JS。踩过的坑都写在这里，**改之前先读**。

## 一、编辑方式（头号纪律）

**一律用 Python 脚本改，不要用编辑器直接改**：

```python
# -*- coding: utf-8 -*-
import io
P = '班级小助手.html'
s = io.open(P, encoding='utf-8').read()
def rep1(old, new, tag):
    global s
    assert s.count(old) == 1, '[%s] 期望 1 处，实际 %d 处' % (tag, s.count(old))
    s = s.replace(old, new)
    print('OK', tag)
rep1('旧字符串', '新字符串', '标签')
io.open(P, 'w', encoding='utf-8').write(s)
```

原因：编辑工具（`Edit` 等）在这个大文件上**会静默漂移**——返回「成功」但内容没落盘，且很难发现。`assert count==1` 还能顺带防止误替换多处。

改完**必须复核**（重新读取并搜索改动处），不要相信任何「已保存」的提示。

## 三、改功能时的架构红线

1. **派生数据必须三点同步**
   典型：小组成员 `state.pk.groups[].members` 是从座位表 `state.seatBase` 派生出来的。历史 bug：座位变了小组成员不变。同步点必须接三处——
   - 全局重绘 `rerenderAll()` 里、目标渲染函数**之前**
   - `save()` 开头（落盘兜底，保证导出包自洽）
   - 所有「只调局部渲染」的入口（如轮换座位按钮只调了 `renderSeating()`）

   同步函数要**幂等**、**只动派生字段**、**源数据为空时安全返回不清空**。

2. **首启路径 ≠ 迁移路径**
   新装机器 `state = defaultState()`，**不走 `load()` 里的迁移/归一化代码**。新增容器字段（如 `schedSets`）必须惰性初始化，并在 `let state = ...` 之后立即调用一次，否则新装机器上功能静默失效。

3. **换机包导出的是 state 快照**
   如果某字段能从别的字段算出来，迁移时记得重建；别指望快照里一定是最新的。

4. **设置指纹不要计入派生字段**
   `settingsCanonicalObj()` 里若同时包含源字段与派生字段，两者不同步时会误报「设置不一致」。派生字段不进指纹。

## 四、样式作用域

**公共按钮尺寸必须写在全局**。历史 bug：`.btn-single` / `.btn-ten` 只写了背景色，尺寸规则被写在 `.gacha-btns button` 作用域里，导致用到别处（点名、倒计时）时退回浏览器默认 28px 高。

触摸目标尺寸下限：≥44px（教室大屏建议 ≥60px）。

## 五、滑块/输入类控件

`input[type=range]` 必须同时绑 `input` 和 `change`（只绑一个在某些交互下不触发）。历史 bug：倒计时滑块完全没绑事件，拖动时数字不变。

## 六、提示文字规范

- 大屏投影页的提示：能删则删，保留的压到 **≤1 行 ≤28 字**
- 详细说明移进 `title` 属性（鼠标悬浮），**不要真删信息**
- 设置面板的说明可以保留（老师配置时才看）
- 改提示后跑对应的回归断言（提示清理相关）

## 七、给 AI 的排查清单（遇到「改了没反应」）

1. 目标渲染函数读的是**快照字段**还是**源字段**？
2. 唯一会重算快照的函数挂在哪些入口？是不是只在手动按钮上？
3. 列全所有修改源字段的入口，逐个确认是否触达重算——**最容易漏「只调局部渲染」的那个**
4. 改动有没有真的落盘？（复核！）

## 八、不要做的事

- 不要用 CSS `zoom` 作用在根元素上（4K 大屏字号偏小应建议系统缩放）
- 不要在 SVG 内联里写 `width`/`height` 属性（会覆盖 CSS 的 `clamp`）
- 不要把真实学生/学校名写进模板（分发前必查）
- 不要改 `localStorage` KEY 后还指望老数据能读回来（KEY 变了等于换新存档）

## 九、数据持久化（第十一轮定稿：教室电脑会「还原」）

**背景**：教室一体机常装系统还原（冰点还原/影子系统），重启后浏览器 profile 连 localStorage 一起被清空。
表现是「今天改的都白改了，第二天打开又回到初始班级」。**这不是代码 bug，是存储环境不可靠。** 因此：

1. **写后自检**：`save()` 之后必须回读比对，并把失败原因（配额/被禁用/读不到）报出来，
   用**常驻横幅**告警（不是 1.6 秒的 toast）。`save()` 是全局函数，可以在另一个 `<script>` 里
   用 `save = wrapped` 覆盖（顶层函数声明是全局对象属性，重赋值对所有调用点生效）。
2. **数据要落到「文件」上**，不能只依赖 localStorage：
   用 File System Access API 让老师绑定**程序文件本身**，之后每次保存把最新 state 内嵌写回该文件。
   第二天双击同一个文件 → `load()` 读到内嵌数据 → 零操作恢复。
   - 句柄存 IndexedDB（`FileSystemHandle` 可结构化克隆），开机用它自动找回。
   - 写盘前先自检生成内容（长度、数据标记、`</body>`/`</html>`）——**不合法就拒绝写**，
     宁可数据只在浏览器里，也不能把老师的程序文件写坏。
   - 写盘后回读校验；报错用常驻横幅并给出「改用导出数据包」的退路。
   - 内容指纹没变就不重复写盘。
3. **内嵌数据脚本必须插在 `<body>` 之后、程序脚本之前**。
   ⚠️ 历史 bug：插在页面最末尾时，主脚本里的 `load()` 执行时 `window.__CLASS_EMBEDDED_STATE__` 还没定义，
   **「双击换机包自动读回」一直是失效的**。老格式的文件要在程序跑起来后补读一次（`adoptEmbedded()`）。
4. **剥离上一轮注入的数据脚本必须用 DOM 节点精确删除，绝不能用文本正则**。
   ⚠️ 灾难性 bug：程序源码里也含 `<script>window.__CLASS_EMBEDDED_STATE__=` 这样的字面量，
   文本正则会从源码里的字符串一直删到下一个 `</script>`，**把程序自身代码删掉，写回的文件变成坏文件**。
   正确做法：克隆 `documentElement`，遍历 `querySelectorAll('script')`，只删 `textContent` 以
   `window.__CLASS_EMBEDDED_STATE__` 开头的那一个；顺带清理 `<body>` 上的 `editing`/`dragging` 类。
   注入标签也用 `'<scr'+'ipt ...'` 拼出来，让源文件里不出现可被误匹配的纯文本锚点。
5. **全量数据包**：导出 `.json` 要带元信息（app/schema/时间/班级/人数/指纹/校验和/字节数），
   导入要能识别三种来源（裸 state / 带壳数据包 / 带数据的 html），并且**导入前先留一份 `_prevmig` 备份**。
6. **开机找回**：本机没存档时不要静默变成空班级。顺序是
   ① 内嵌数据（老格式补读）→ ② IndexedDB 里记住的文件句柄 → ③ 弹出「找回数据」面板
   （打开 .json / 打开带数据的 html / 立刻绑定 / 确认是新班级）。
7. **绑定提醒不要做成顶部横幅**——横幅会盖住右上角的 ⚙ / 💾 按钮。用顶栏脉冲小徽章。

### 对应回归测试
- `n19` 存档持久化（跨日往返 / 备份键救回 / 换机包不被旧数据回滚）
- `n20` 第十一轮专项 89 条（保存自检、告警常驻、数据包结构、三种来源识别、导入往返、坏文件拒绝、

## 十、冗余字段的一致性（第十二轮：积分「无声清零」事故）

**事故**：积分页工具栏上「⚠️ 重置全部积分为0」与「↺ 重置今日积分」并排。
`#scoreReset` 只做 `students[].score=0`，**没有同步 `state.daily` 历史记录**。
老师（或学生乱点）误按后，累计积分显示为 0、看着像"积分全丢了"，
而历史记录其实完好——但界面上没有任何地方能把它算回来，也没有撤销。

**通用教训**：同一个业务量存在两份表示时（这里是
`students[].score`（累计）与 `daily[日期][学生id]`（每日明细，两者本应恒等：
`score === Σ_d daily[d][id]`），任何"重置/清零/撤销"操作都必须**同时处理两份**，
或者提供**从明细重算**的补救路径。只改一份 = 静默不一致。

**本轮的三个修法（可复用的模式）**：
1. **危险操作前留快照**：`snapshotScores(label)` 把逐人分数存进 `state.scoreSnap`，
   并在工具栏亮出「↩ 撤销积分改动」按钮（`restoreScoreSnap()`）——把不可逆操作变成可逆。
2. **自检横幅 + 一键修复**：`scoreGap()` 比较 `Σdaily` 与 `Σscore`，差额 > 0 时在页面内
   显示横幅说明差异并给「🧮 按历史记录补回积分」（`repairScoresFromDaily()`）。
   修完差额归零、横幅自动收起。**保留「是我故意的，不再提示」**——老师可能真的想清零，
   但要记住该选择（把抹掉的差额存进 `state.scoreRepairHideGap`，差额再变大时才重新提醒）。
3. **危险按钮要长得危险**：加 ⚠️ 前缀、红边红字、`title` 写清"会清累计分、历史保留、可撤销"，
   并在确认框里明确指向正确的那个按钮（"只想清今天的加分请用「↺ 重置今日积分」"）。

**顺带定下的排查口诀**：看到"某个数字突然变 0 / 变空"，先问
**"这个数字是从哪算出来的？有没有第二份来源？清空它的那条代码路径有没有同步另一份？"**

### 对应回归测试
- `n21` 积分自检与补救 42 条：差额计算、横幅显隐、一键补回、撤销、`#scoreReset` 可撤销、
  `#todayReset` 不产生差额、锁定/空名单/无历史等边界、`daily` 与 `score` 恒等性。

## 十一、统计视图的数据源：一律从明细重算（第十三轮）

承接第十章。凡是**给人看数字**的统计/排行/趋势，都从**明细流水**重算，不要读缓存字段：

- 明细：`state.daily['YYYY-MM-DD'][学生id]` —— 逐日流水，是唯一的真相
- 缓存：`students[].score` —— 只在积分卡片上显示；它被"清零""撤销""换名单"动过，历史包袱多
- 推论：`Σ_daily(全部日期) === Σ_daily(每月) === 总积分`，三者必须恒等（写测试断言它）

这样即使缓存字段被误清零，**排行/趋势仍然正确**，老师也不会觉得"数据丢了"。
新加的「🏆 总积分」「📈 月度趋势」就是这么做的（`dailyTotalOf` / `monthTotalOf`）。

### 加新视图的落地方式（低风险）
不要改老视图的渲染函数，而是在**分流函数**顶部加一行 `if(period==='xxx'){ renderXxx(); return; }`，
新视图写成**独立的叶子渲染函数**（只读数据 + 写 DOM）。这样：
- 老视图零风险（回归测试 H 段就是守这条）
- 新视图自己有独立的 CSS 类名，不会挤坏老布局
- 页签是静态 HTML 里的 `<button data-r="xxx">`，加载时那段绑定代码自动覆盖新页签

### 大屏布局取舍
34 人的班级要用 **3 列紧凑列表**（每行 ~24px，12 行 ≈ 290px）才装得下；
一条"迷你折线"用 `viewBox` + CSS 定尺寸（**不要在 SVG 上写 width/height 属性**），
`104×26` 放进 flex 行里最稳。加完必须跑 1920×1080 与 2560×1440 的**零溢出**断言
（新增视图往往是全页最高的那个）。

## 十二、文件解析：源码里的同名文本是头号陷阱（第十四轮）

`parseStateFromAny(txt)` 要能从三种东西里读出 state：新格式数据包 json、老格式裸 state json、
带数据的 html。**难点全在 html**：

1. **程序自身源码里就含 `window.__CLASS_EMBEDDED_STATE__=` 这段文本**（脱敏后的模板名）
   （`buildExportHtml` / `buildSelfHtml` 里是拼字符串），而且 `'<script>'`、`'</body>'` 也是字面量。
   所以**任何"在全文里找标记 → 正则截取"的做法都会踩雷**：
   - 取第一处 → 老格式文件命中的是源码里的字面量（真数据在页面末尾）→ 解析失败
   - 取最后一处 → 新格式文件命中的是源码里的字面量（真数据在 `<body>` 之后）→ 解析失败
   - 正则 `([\s\S]*?);window.__CLASS_EXPORT_META__=` → 在源码里也能匹配上一大段垃圾

   **正确做法：把所有出现位置都当作候选，逐个用「括号配平扫描」取到配对的 `{...}`，
   再 `JSON.parse`，返回第一个解析出「含 students 数组」的对象。** 顺序无关，靠结果校验。
   扫描要带 `inString` / `escape` 状态，并设一个长度上限（防在源码里扫到文件尾）。

2. **UTF-8 BOM**：早期版本的 `dlText` 会给导出的 json 加 `\ufeff`（为了 Excel 打开 CSV 不乱码），
   而 `JSON.parse` 遇到开头 BOM **直接抛错**。解析前先 `charCodeAt(0)===0xFEFF` 去掉。

3. **`accept` 属性会把老师挡住**：`<input type="file" accept=".json">` 会让 `.html` 文件在
   系统文件列表里**根本看不见**。既然解析层支持 html，就把 accept 放开成
   `.json,application/json,.html,.htm,text/html`。

4. **验证要用真实文件**：把老师目录下的**每一个**历史备份都当测试输入（新版包/老版 json/
   换机包 html/含数据 html/带 BOM 的早期备份），断言"能解析 + 关键字段正确 + 三种格式解析结果等价"。
   测试时注意 Node 没有 `os.path.expanduser`（那是 Python 的），用 `path.join(os.homedir(),...)`。

5. **重载会清空 DOM**：验证"导入后自动刷新"的探针必须把结果写进 `localStorage` 带过重载，
   否则 `--dump-dom` 只能看到重载后的 DOM，第一阶段的结论全丢。

## 十三、教室电脑的写保护（第十五轮：让老师自己一眼判断）

教室一体机普遍装**系统还原 / 冰点还原**：重启把 C 盘恢复原样。对这类环境有三条硬结论：

1. **程序能跑，数据会丢**。单文件离线 HTML 放哪都能跑；但 `localStorage` 在
   `C:\Users\…\AppData` 里，跟着 C 盘一起被还原 → **数据不能只放浏览器**。
2. **桌面的"下载/桌面"也是 C 盘**。把 html 放桌面/下载，第二天**连文件本身都会被还原**，
   绑定它毫无意义。必须引导老师放到 **D 盘 / U 盘**。这一条最容易踩，务必写进交付说明。
3. **绑定句柄会忘、数据不会丢**。句柄存 IndexedDB（也在 C 盘）→ 每天重启后要重新授权；
   但数据已经写进 html 了，`load()` 靠内嵌数据自动读回，**零点击恢复**。所以句柄丢失不是问题。

### 「🩺 本机安全自检」的实现要点（可复用）
- `progPathInfo()`：解析 `location.pathname`，用 `/^\/([A-Za-z]):\//` 取盘符；
  `C` → 风险，其他盘符 → 提示安全，无盘符（非 Windows 的挂载路径、UNC）→ 不误报
- `runSelfTest()` 做三项检查并给**一句话结论**：
  ① `localStorage` 写后读回（区分 QuotaExceeded / SecurityError / 读不回）
  ② 本机存档是否存在且够大
  ③ 已绑定则**真的写一次文件**并回读校验（`writeSelfFile('selftest', true)`）
- 结论分档：全绿→「可以放心用」；未绑定→「建议做一次绑定」；写回失败→红；
  浏览器禁止保存→红并催导出；C 盘→额外一行红色警告
- **结果必须 `scrollIntoView`**：设置面板很长，输出块常在视口之外 —— 老师点完看不到结论等于没做
- 用「三项逐条 ✓/✗」的写法而不是只给一个总结论，出问题时老师能自己说清哪一步不行

## 十四、座位方案（第十六轮：把"单槽快照"升级成 3 个槽）

老师需要几套座位随时切换（常规 / 考试 / 分组活动）。原来只有一个 `state.seatTeacher` 槽，
存新的就把旧的挤掉。改成 `state.seatPlans=[{name,base,at}|null ×3]`。

### 交互设计（最容易做错的地方）
用户的原话是「按 1 再点保存」＋「随时切换回 3 种结果」——**这两句对"点数字"的期望是矛盾的**：
按 1 是"选保存目标"，切换回是"取出来用"。硬混会导致"我只想覆盖方案2，一点却把当前座位切走了"。
最终做法：
- **点空槽 = 只选中（设为保存目标）**，不动座位；💾 按钮文案跟着变成「存入方案N」
- **点有内容的槽 = 立即切换**（最高频动作，1 次点击）
- **要覆盖已有槽** → 点「💾 存入方案…」→ 弹出 ①②③ 三选一（覆盖前 confirm）
- **长按/右键槽** → 该槽的菜单（改名 / 清空）；`pointerdown` 起 650ms 定时器 + `contextmenu`，
  长按后要吞掉随之而来的 `click`（`longFired` 标志），否则"改名完顺手把座位切走了"

### 必须同步的三件事（漏一个就出 bug）
1. **`rerenderAll()` 而不是 `renderSeating()`** —— 座位变了，积分页与竞赛分组必须跟着变
   （`syncPKMembersToSeat` 在 rerenderAll 里跑）
2. **重置轮换基准**：`seatBaseDate=本周一; seatRotation=0`，否则刚切过去就被
   `applyAutoRotation()` 按周轮换打乱
3. **格数校验**：`plan.base.length !== state.seatBase.length` → 拒绝切换并说明原因
   （换过名单/改过组数后旧方案会错位）

### 配套细节
- 切换前把当前座位存进 `state.seatPlansTmp` → 出「↩ 切回上一个」按钮，点错能退
- 老数据迁移：`ensureSeatPlans()` 把 `seatTeacher` 搬进 `seatPlans[0]`（起名「初始座位」）并清空旧字段；
  在 `let state=load()||defaultState()` 之后**立即调用**一次（首启不走 load 路径，参考第四章）
- 换名单 / 改组数的 handler 里要把 `seatPlans` 一并清空
- **不要用模块级 `const SEAT_PLAN_N` 去给 `ensureSeatPlans()` 用**：它在 `let state=` 之后立刻被调用，
  而该 const 声明在文件后段 → TDZ 抛错。槽数直接写字面量 3（或声明在文件最前面）

## 十五、大屏工具栏的"三步走"排布（第十七轮）

班主任在教室里是**照从左到右的顺序操作**的，所以工具栏的顺序就是操作顺序：
`① 排布 → ② 方案 → ③ 轮换`。做法与收益：

- 用 `span.step-lab` 做圆形步骤标签（`cursor:help` 提示可悬浮），**编号本身就是引导**
- 把每个控件的作用写进各自 `title`，`&#10;` 换行分条列出（悬浮里可以看多行）
- **动态状态提示（`#seatPlanHint`）与静态说明分开**：静态说明一律进 title；
  页面上的提示条**只在"真有事"时才写内容**，否则 `textContent=''` —— 空 span 宽度为 0，天然不占版面
- 实测收益：删掉一句橙色说明 + 通用引导 + 缩短顶部提示后，工具栏从 **两行 81px 压到一行 52px**
- 代价很小、可逆性高：这类"把说明挪进悬浮"的改动**必须同步跑提示文字类断言**
  （本项目 n17 有 12 条提示清理断言、n25 有顺序/悬浮断言），否则会误判为回归

### ⚠️ 样式被全局按钮规则覆盖（第十八轮踩的坑）
本文件有一条 `.toolbar button, .mini-btn{ border:2px solid …; background:#fffdf7; }`。
**它的优先级 (0,1,1) 高于单个类 `.seat-plan` (0,1,0)** —— 于是给方案按钮写的
`border-style:dashed; background:transparent`（"空心虚线"）被静默覆盖，看起来全是实心，
`min-height` 也被拉到全局按钮的高度。**教训：在 `.toolbar` / `.mini-btn` 的势力范围内写自定义按钮样式，
选择器必须带上容器前缀**（如 `.seat-plan-bar .seat-plan`，(0,2,0) 才压得住）。

### "只在有状态时才占位置"的提示条
`#seatPlanHint` 用 4~5 个字表达状态（「将存到 ①」/「正在用 ①」），无状态时 `textContent=''`。
**这是"既要反馈、又要一行放得下"的关键技巧**：静态说明全进 `title`，动态反馈极简且可空。

### 数"工具栏占几行"的正确写法（真机量测）
不能把子元素的 `top` 去重 —— 同一行内元素高度不同、基线对齐会让 `top` 差好几像素（实测同一行出现 5 个不同 top）。
正确做法：**按纵向区间聚类**（排序后若下一个元素的 top ≥ 当前行 bottom−2px 则算新行），
或直接看工具栏 `getBoundingClientRect().height`（1 行 ≈ 52px，2 行 ≈ 81px）。

### 开机「未绑定」常驻提醒（第十九轮，2026-09-18）
- 还原卡机器**每天开机绑定授权都会丢** → 未绑定期间加分只在 localStorage（C 盘）→ 关机即丢。这是「当日积分丢失」的根因
- 新增 `state.lastBindName`（绑定成功时记录文件名；手动解绑时清空；load 归一化补齐）
- 持久化脚本开机分支：`idbGet(IDB_SELF)` 恢复不了句柄且 `state.lastBindName` 非空 → `showAlert(...,{sticky:true})` 常驻黄条；**从没绑定过的不弹**（保持新机友好引导）
- 自检未绑定分支区分两种情况：从未绑定 → 「建议做一次绑定」；绑定过被清 → 「每次开机后都要重新点一次绑定」
- 页脚「未绑定文件」改为「未绑定文件（新加分未写进文件）」——状态要连后果一起说
- 教训：只靠页脚小字提醒不够，老师看不懂「未绑定」的后果；**提醒必须带「会导致什么丢失」和「现在点什么」**

## 十六、状态提醒的"可见性"原则（第十九轮）

老师不会去看页脚小字。凡是「数据可能丢」这类需要老师**立刻动手**的状态，必须满足三条：

1. **说清后果**：不写「未绑定文件」，要写「未绑定文件（新加分未写进文件）」；
2. **给出下一步动作**：提醒条上直接放可点的按钮（`#saveAlertFix` 绑定 / `#saveAlertPack` 导出）；
3. **常驻不被顺手关掉**：`showAlert(kind, title, msg, {sticky:true})`，且成功保存不会清掉它（`hideAlert(force)` 才关）。

**不要对所有人都弹**：只在「这台电脑以前绑定过、今天授权被清了」时弹（判据：`state.lastBindName` 非空且当前未绑定）。
从未绑定过的电脑保持安静——新用户第一次见到满屏告警会直接关掉程序。
配套：`state.lastBindName` 在绑定成功时写入、手动解绑时清空、`load()` 归一化补齐（老存档自动补）。

## 十七、分数口径改动要"全局一致"（第十九轮b：允许负分）

"能不能减到负分"不是一个按钮的事，而是**一整条链路口径**。改动时务必全局搜索夹取点：

```
Math.max(0, s.score …)      // 学生累计分
Math.max(0, daily[...] …)   // 每日明细
```

本项目一次改到 6 处：卡片点击（`addScore(id,e,delta)`）、撤销（`undo`）、重置今日（`todayReset`）、
全体加分（`#scoreAll`）、小组加分、趋势图补记（`patchRecord`）。
剩下的 `Math.max(0,` 属于等级/星数/RGB/周数计算，**不要动**——判断依据是看它夹的是不是"分数"语义。

显示层同样要跟：`今日 +${todays}` 这样写死加号，负数会显示成「今日 +-3」，
要写成 `今日 ${todays>=0?'+':''}${todays}`（本项目涉及学生卡 2 处 + 排行页 2 处）。

**交互设计**：不要做"给最后点过的学生减 1"这类按钮——老师必须先点学生（+1）再减（−1），净效果 0，像撤销。
正确做法是**模式开关**：开「减分模式」后，点学生卡＝减分，再点关闭；
开启时用三重视觉提示（按钮变红 + 页面顶部红条 + 学生卡红框）防止忘记关闭。


## 十八、批量改写 CSS：`@media` 与 `@keyframes` 的头会被吃掉（2026-09-23 两次事故）

对 `<style>` 做「逐规则正则改写」（例如全局加 `var(--fs)` 缩放）时，凡是**行头含 `{` 的 at 规则**——
`@media(...){`、`@keyframes NAME{`——都会被当成普通规则的选择器处理掉：**头没了、闭括号也没了**，
body 原地裸奔变成全局生效。后果非常隐蔽：

- `@media(max-width:1600px)` 的「小窗可滚动」规则全局生效 → 大屏也开始滚动，破坏「一屏不翻动」
- `@media(max-height:800px)` 里的 `.duty-tile{font-size:calc(12px*var(--fs))}` 全局生效 → 大屏字号被钉死变小
- `@keyframes` 全灭 → 页面上**所有动画静默失效**（升级特效、火箭发射、加分飘字、抽卡……），且无任何报错

**纪律（两条都必须做）：**

1. **改前记数、改后比对**：
   ```bash
   grep -c '@media' 文件.html; grep -c '@keyframes' 文件.html   # 改前记下
   # 改完再跑一遍，数量必须与改前一致
   ```
   `animation:XXX` 的每个引用都必须能找到 `@keyframes XXX` 定义，一个都不能少。
2. **恢复方法**：从备份用「括号配平」提取原始块，回当前文件定位孤儿 body 后重新包上
   `@media(...){ body }` / `@keyframes NAME{ body }`。孤儿 body 的特征：
   - 顶层出现连续的 `0%{...}50%{...}100%{...}` / `from{...}to{...}` 片段（注意 `h1{`、`50%{opacity:.45;}` 这类选择器会干扰正则，必须配合「顶层深度=0」判断）
   - 位置通常紧贴在引用它的那条规则前面或后面
   - 同名动画在草稿和正式版里数值可能不同（如 petjump 的跳跃高度调过），**以当前文件的 body 为准**，别拿草稿硬套
